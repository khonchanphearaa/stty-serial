# tty_serial v0.1 plan: Serial + TCN board

This is the build plan for the first version of `tty_serial`. It records the
decisions already made, the project structure, the native channel contract,
the public Dart API, and the build steps in order. Read `CLAUDE.md` first for
toolchain and rules; this file does not repeat them.

## 1. How we work (teaching mode)

The developer types the code. The assistant guides.

- Work **one step at a time** from section 7. Never jump ahead.
- For each step, give:
  1. the goal, in two or three sentences;
  2. every file to create or change, with its full path;
  3. the **complete** file content in one code block (no `...`, no "rest
     unchanged"); for a change to an existing file, show the whole new file
     or an exact before/after;
  4. a short explanation of the important lines: why, not what;
  5. the command that checks the step, and the expected result.
- Then **stop and wait** until the developer says the step is done.
- When the developer says done: read their files, compare with the plan,
  point out mistakes (with line numbers), run the check commands, and report
  the real output.
- Do not create or edit code files yourself unless the developer says
  "write it for me" for that step. Reading files and running checks is fine.
- Use simple English. Explain Flutter, Dart, Java, and Android terms the first
  time they appear.

## 5. Native channel contract

One `MethodChannel` named `tty_serial`. Every method runs off the UI thread
and replies on the main thread. Java validates every argument; a bad one
fails with `invalidArgument`.

| Method | Arguments | Returns |
| --- | --- | --- |
| `listPorts` | `prefixes: List<String>` | `List<String>` paths, sorted, at most 32 |
| `open` | `path: String`, `prefixes: List<String>`, `baudRate: int`, `dataBits: int`, `parity: String`, `stopBits: int` | `int` handle |
| `write` | `handle: int`, `data: Uint8List` | `null` |
| `transact` | `handle: int`, `data: Uint8List`, `replyLength: int`, `timeoutMs: int` | `Uint8List`, maybe shorter than `replyLength` |
| `close` | `handle: int` | `null` (closing a closed handle is fine) |
| `stopProcess` | `program: String` | `bool`: true when no such process is left running |

**Limits:**
- `prefixes`: 1-8 items, each matching `^tty[A-Za-z]{1,8}$`. Default from Dart: `ttyS`, `ttyUSB`, `ttyACM`.
- `path`: must match `^/dev/(<prefix>)[0-9]{1,3}$` for one of the given prefixes, exist, and be readable and writable.
- `baudRate`: one of 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200.
- `dataBits`: 7 or 8. `parity`: `none`, `even`, or `odd`. `stopBits`: 1 or 2.
- `data`: 1-256 bytes. `replyLength`: 1-256. `timeoutMs`: 1-30000.
- `program`: `^/system/(x)?bin/[A-Za-z0-9_.-]{1,64}$`.

**Error codes** (`PlatformException.code`, with a message for logs):
`invalidArgument`, `notFound`, `permissionDenied`, `busy` (path already open
in this app), `configFailed` (`stty` failed), `closed` (unknown or closed
handle), `io` (read or write failed).

**Behavior to port from the vending app:**
- `stty` command: `stty -F <path> <baud> cs<7|8> <parity> <-cstopb|cstopb> raw -echo -crtscts -ixon -ixoff clocal cread`,
  parity `-parenb` / `parenb -parodd` / `parenb parodd`. Run it while our own
  file descriptor is open (otherwise the settings reset). Try `sh -c "busybox stty ..."`
  first, then `su -c "busybox stty ..."`.
- Shell: 10 s timeout, poll `exitValue()` every 20 ms (`waitFor(timeout)` needs
  API 26), read output on a daemon thread, wait at most 500 ms for it after exit.
- `transact`: first discard waiting input (at most 256 bytes), write and
  flush, then poll `available()` every 10 ms until `replyLength` bytes or the
  deadline (`SystemClock.uptimeMillis()`). Return what arrived. A short
  result is not an error.
- Each handle has its own single-thread executor, so commands on one port stay
  in order and a slow port never blocks another. `listPorts` and
  `stopProcess` use one shared executor.
- `PortRegistry`: a path can be open only once in the app (`busy` otherwise).
- `onDetachedFromEngine`: close every handle, shut down every executor.
- `stopProcess(program)`: find PIDs whose `/proc/<pid>/cmdline` program equals
  `program` (no root needed); if none, return true without `su`. Otherwise run
  `su -c "stop <basename>; kill -9 <pids>"`, then check again up to 5 times,
  200 ms apart. PIDs must match `^[0-9]{1,7}$`. Never called by `open`.

## 6. Public Dart API

```dart
// package:tty_serial/tty_serial.dart
enum BaudRate { b1200, b2400, b4800, b9600, b19200, b38400, b57600, b115200 }
enum DataBits { seven, eight }
enum Parity { none, even, odd }
enum StopBits { one, two }

final class SerialConfig {
  const SerialConfig({
    this.baudRate = BaudRate.b9600,
    this.dataBits = DataBits.eight,
    this.parity = Parity.none,
    this.stopBits = StopBits.one,
  });
  // + ==, hashCode, toString ("9600 8N1")
}

sealed class SerialException implements Exception { String get message; }
// SerialInvalidArgument, SerialPortNotFound, SerialPermissionDenied,
// SerialPortBusy, SerialConfigFailed, SerialPortClosed, SerialIoException,
// SerialUnsupported (no plugin on this platform, e.g. tests or web)

abstract interface class SerialPort {
  String get path;
  SerialConfig get config;
  bool get isOpen;
  Future<void> write(Uint8List data);
  /// Clears stale input, writes [request], reads up to [replyLength] bytes
  /// until [timeout]. A shorter result means the device did not answer in time.
  Future<Uint8List> transact(Uint8List request,
      {required int replyLength, required Duration timeout});
  Future<void> close();
}

final class TtySerial {
  const TtySerial({this.prefixes = const ['ttyS', 'ttyUSB', 'ttyACM']});
  final List<String> prefixes;
  Future<List<String>> listPorts();
  Future<SerialPort> open(String path, [SerialConfig config = const SerialConfig()]);
  /// Root. Ends a ROM daemon that scans serial ports (e.g. eGTouchD on the
  /// dg3188). Only when the app asks; never called by open().
  Future<bool> stopProcess(String program);
}
```

`TtySerial` is an instance (not static methods) so apps can inject a fake.

```dart
// package:tty_serial/tcn.dart
final class TcnBoard {
  TcnBoard(SerialPort port, {
    int group = 0,              // 0-255
    int firstLane = 1,          // 1..lastLane
    int lastLane = 60,          // up to 80 (0x50, the PDF's limit)
    Duration replyTimeout = const Duration(seconds: 5),
    Duration motorTimeout = const Duration(seconds: 15),
  });

  /// Runs one lane's motor. Never retried. Exhaustive result on purpose.
  Future<DispenseOutcome> dispense(int lane, {bool dropCheck = false});

  /// Throws TcnException on fault / no reply / bad reply. Safe to retry.
  Future<int> readTemperature();       // signed °C
  Future<void> setLed(bool on);        // safe to retry

  bool get busy;                       // a command is on the wire
}

sealed class DispenseOutcome {}
// DispenseDelivered({bool? dropDetected})   drop seen, or motor done with check off
// DispenseNotDelivered(String reason, {MotorStatus? motor, DropSensorStatus? sensor})
// DispenseUnknown(String reason)            may have turned: never run again automatically
// DispenseNotSent(String reason)            nothing reached the wire

sealed class TcnReply {}   // TcnAccepted(data, dropDetected), TcnFault(motor, sensor, raw),
                           // TcnNoReply(received), TcnBadReply(reason)
enum MotorStatus { normal, pMosShort, nMosShort, motorShort, motorOpen, rotationTimeout, unknown }
enum DropSensorStatus { normal, signalWithoutEmitter, noSignal, constantSignal, unknown }
sealed class TcnException implements Exception {}  // TcnFaultException, TcnNoReplyException, TcnBadReplyException

final class SlotLayout { ... }       // rows, columns, pair starts; motorFor(slot)
```

**Why two result styles:** `readTemperature` and `setLed` are safe to repeat,
so failure is an exception and the caller may retry. `dispense` is not safe to
repeat, so it returns a sealed outcome; a `switch` must handle `unknown`
explicitly, which a forgotten `catch` cannot do.

**Outcome mapping** (from `BoardService.dispense`):

| What happened | Outcome |
| --- | --- |
| Lane outside `firstLane..lastLane`, or port closed before writing | `NotSent` |
| `SerialException` during `transact` (except `SerialPortClosed`) | `Unknown` (the packet may be on the wire) |
| `TcnAccepted`, drop detected | `Delivered(dropDetected: true)` |
| `TcnAccepted`, no drop, `dropCheck` on | `NotDelivered('Motor ran, no drop detected')` |
| `TcnAccepted`, `dropCheck` off | `Delivered(dropDetected: null)` |
| `TcnFault` | `NotDelivered` (motor status; sensor status only when `dropCheck` is on) |
| `TcnNoReply` or `TcnBadReply` | `Unknown` |

**Command check** (`tcn_packet.dart`, private, called by `TcnBoard` before every
write). Allowed: group equal to the board's group, and:
- a lane in `firstLane..lastLane` with supplement `0x55` (no drop check) or `0xAA` (drop check);
- `0xDD` (LED) with `0xAA` (on) or `0x55` (off);
- `0xDC` (temperature) with `0x55`.

Anything else throws `StateError` (a bug in the package, never sent).

**Queue:** `TcnBoard` runs one command at a time with a `Future` chain (FIFO),
like `BoardService._exclusive`.

## 8. Fixture layouts (step 15)

`tcn_script_packets.json` is a list of `[layout, slot, dropCheck, packet]`
rows: 4 layouts × 60 slots × 2 = 480 rows. The layouts:

| Name | Pairs (first slot of each pair) |
| --- | --- |
| `single` | none |
| `default` | row 2 double: 11, 13, 15, 17, 19 |
| `row3` | row 3 double: 21, 23, 25, 27, 29 |
| `rows2and3` | rows 2 and 3 double |

For every row, `buildPacket(layout.motorFor(slot), dropCheck ? 0xAA : 0x55)`
with group 0 must equal `packet`.
